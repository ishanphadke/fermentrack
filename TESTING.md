# Testing Guide for Fermentrack

This document explains how to run tests for the Fermentrack project and resolve common issues.

## Prerequisites

Before running tests, ensure you have:
- Flutter SDK installed (3.9.2 or higher)
- All dependencies installed
- Generated code files created

## Quick Start

### 1. Generate Required Code Files

The project uses code generation for:
- **Freezed** - Immutable data models (`.freezed.dart`)
- **JSON Serialization** - JSON conversion (`.g.dart`)
- **Riverpod** - Provider code generation (`.g.dart`)
- **Mockito** - Test mocks (`.mocks.dart`)

Run the generation script:

```bash
./generate_code.sh
```

Or manually:

```bash
flutter pub get
flutter pub run build_runner build --delete-conflicting-outputs
```

### 2. Run Tests

After code generation, run tests:

```bash
# Run all tests
flutter test

# Run specific test file
flutter test test/models/project_test.dart

# Run tests with coverage
flutter test --coverage

# Run tests in verbose mode
flutter test --verbose
```

## Common Issues and Solutions

### Issue 1: "No such file or directory" for `.freezed.dart` or `.g.dart` files

**Error:**
```
Error: Cannot run with sound null safety, because the following dependencies don't support null safety:
 - package:fermentrack/models/project.dart (via package:fermentrack)
   'file:///path/to/lib/models/project.freezed.dart' not found
```

**Solution:**
Run the code generation script:
```bash
./generate_code.sh
```

### Issue 2: "Cannot find mock class" or `.mocks.dart` not found

**Error:**
```
Error: Could not resolve the import 'firestore_service_test.mocks.dart'
```

**Solution:**
The mock files are generated by build_runner. Run:
```bash
flutter pub run build_runner build --delete-conflicting-outputs
```

### Issue 3: `invalid_annotation_target` warnings

**Error:**
```
warning: The annotation 'JsonKey' can only be used on fields
```

**Solution:**
This is expected with Freezed 3.0+. The warning is suppressed in `analysis_options.yaml`:
```yaml
analyzer:
  errors:
    invalid_annotation_target: ignore
```

### Issue 4: Missing `json_annotation` dependency

**Error:**
```
Error: You are missing a required dependency on json_annotation
```

**Solution:**
This has been added to `pubspec.yaml` in the dependencies section. Run:
```bash
flutter pub get
```

### Issue 5: Build runner conflicts

**Error:**
```
Conflicting outputs were detected
```

**Solution:**
Use the `--delete-conflicting-outputs` flag:
```bash
flutter pub run build_runner build --delete-conflicting-outputs
```

## Test Structure

The project follows a comprehensive testing strategy:

### Unit Tests
- **Location**: `test/models/`
- **Purpose**: Test data models and business logic
- **Example**: `project_test.dart` - Tests Project model immutability, JSON serialization

### Service Tests
- **Location**: `test/middleware/services/`
- **Purpose**: Test service layer with mocked dependencies
- **Example**: `firestore_service_test.dart` - Tests CRUD operations with mocked Firestore

### Widget Tests
- **Location**: `test/frontend/`
- **Purpose**: Test UI components
- **Example**: `project_card_test.dart` - Tests widget rendering and interactions

### Provider Tests
- **Location**: `test/middleware/projects/providers/`
- **Purpose**: Test Riverpod providers and state management
- **Example**: `project_providers_test.dart` - Tests provider behavior and dependencies

## Writing New Tests

### 1. Model Tests (Unit Tests)

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:fermentrack/models/your_model.dart';

void main() {
  group('YourModel Tests', () {
    test('creates instance correctly', () {
      final model = YourModel(/* params */);
      expect(model.field, expectedValue);
    });

    test('serializes to JSON', () {
      final model = YourModel(/* params */);
      final json = model.toJson();
      expect(json['field'], expectedValue);
    });
  });
}
```

### 2. Service Tests (with Mocks)

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:mockito/annotations.dart';
import 'package:mockito/mockito.dart';

import 'your_test.mocks.dart';

@GenerateMocks([YourDependency])
void main() {
  late MockYourDependency mockDependency;
  late YourService service;

  setUp(() {
    mockDependency = MockYourDependency();
    service = YourService(dependency: mockDependency);
  });

  test('performs operation', () async {
    when(mockDependency.method()).thenAnswer((_) async => result);

    final output = await service.operation();

    expect(output, expectedValue);
    verify(mockDependency.method()).called(1);
  });
}
```

### 3. Widget Tests

```dart
import 'package:flutter/material.dart';
import 'package:flutter_test/flutter_test.dart';

void main() {
  testWidgets('renders correctly', (WidgetTester tester) async {
    await tester.pumpWidget(
      MaterialApp(home: YourWidget()),
    );

    expect(find.text('Expected Text'), findsOneWidget);
    expect(find.byType(YourWidget), findsOneWidget);
  });
}
```

- ✅ Run `flutter pub get`

## Best Practices

1. **Always run code generation before tests**
   - Generated files are not committed to git
   - Each developer must generate them locally

2. **Write tests before or alongside code (TDD)**
   - Follow the Red-Green-Refactor cycle
   - Ensures code is testable

3. **Mock external dependencies**
   - Use Mockito for mocking
   - Never make real network/database calls in tests

4. **Test all states**
   - Loading, success, error states
   - Edge cases and null values
   - User interactions

5. **Keep tests fast**
   - Unit tests should run in milliseconds
   - Use mocks instead of real implementations

## Troubleshooting

If tests still fail after following this guide:

1. Clean and regenerate:
   ```bash
   flutter clean
   flutter pub get
   flutter pub run build_runner build --delete-conflicting-outputs
   ```

2. Check Flutter version:
   ```bash
   flutter --version
   # Should be 3.9.2 or higher
   ```

3. Verify all dependencies are installed:
   ```bash
   flutter pub get
   flutter pub outdated
   ```

4. Check for analyzer errors:
   ```bash
   flutter analyze
   ```
